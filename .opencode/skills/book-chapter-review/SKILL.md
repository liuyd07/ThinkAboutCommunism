## 任务

对一个已完成的章节进行系统审查，检查是否符合本书的写作标准和逻辑一致性。

## 审查清单

### 1. 输出格式检查
检查以下五要素是否齐备：
- [ ] **命题**：是否有明确的核心命题
- [ ] **推导过程**：是否有从公理到命题的逻辑推导
- [ ] **支持证据**：是否有至少一个具体历史案例或数据
- [ ] **反对意见**：是否有反例记录和回应
- [ ] **适用边界**：是否有适用条件和限制说明

### 2. 写作原则检查

#### 原则1：不允许空泛论述
- 标记所有没有具体指向的论断
- 检查"可以认为""一般来说"之类无主语的表述

#### 原则2：每个命题必须有历史案例
- 列出每个命题对应的案例
- 标记没有历史案例支撑的命题

#### 原则3：每个章节必须回归核心公理
- 检查章节结尾是否连接了 A1-A5
- 检查论证是否在某个环节依赖公理

#### 原则4：所有反例必须记录
- 主动思考可能的反例
- 检查是否故意回避了明显不利证据

#### 原则5：先寻找反例，再寻找支持证据
- 检查写作顺序是否体现了这个原则

### 3. 逻辑一致性
- 本章论点与 contents.md 中其他章节是否存在矛盾
- 术语使用是否与全书保持一致
- 数据引用是否标注了来源

### 4. ToDo 检查
- 列出所有残留的 [ToDo] 标记
- 判断哪些 ToDo 是必要的，哪些可以删除

## 输出格式

```markdown
# 审查报告：<章节名>

## 整体评价
通过 / 有条件通过 / 需重大修改

## 问题清单
1. **[严重/中等/轻微]** <问题位置>：<问题描述>
   - 修改建议：<具体建议>

2. ...

## 遗留 ToDo
- <ToDo内容> → 建议：<处理方式>

## 章末公理回归
- [ ] 回归 A1（组织作为竞争单元）
- [ ] 回归 A2（组织间资源竞争）
- [ ] 回归 A3（生产力决定资源规模）
- [ ] 回归 A4（生产循环强化生产力）
- [ ] 回归 A5（正循环扩张）
```
